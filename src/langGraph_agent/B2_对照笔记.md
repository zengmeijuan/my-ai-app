## 2. LangChain 三层抽象

| 层 | 是什么 | 用过的实物 |
|---|---|---|
| Message | 模型无关的统一消息格式 | HumanMessage（("user", t) 简写自动转）；SystemMessage 每轮重注入；AIMessage（content 与 tool_calls 可并存）；AIMessageChunk（碎片可加 = 完整消息，原版手搓重组的框架内实现）；ToolMessage（必带 tool_call_id 配对，漏了 API 400） |
| Model | ChatModel 统一接口，换模型只换构造参数 | ChatOpenAI 接网关；bind_tools / with_structured_output 都返回**新**模型对象，原 llm 不变；裸 invoke 纯文本调用 |
| Runnable | invoke / stream / batch 统一协议 | llm、graph、子图、包装模型手感全同；图编译后是 Runnable，所以能藏进 @tool 里 invoke——组合能递归的根 |

## 3. 核心结论（准绳）

- 模型无状态：记忆不是模型自带的，是框架每轮把历史重新喂进上下文
- state 是黑板：节点只读写自己关心的字段，返回 schema 外的 key 会报错；不同 schema 的图不能直接连线
- 子图封装准绳：主图只要「结果」→ 封装进工具；要干预「过程」（暂停/重派）→ 才升格节点嵌套
- TypedDict 给可信内部数据（纸面契约），BaseModel/pydantic 给 LLM 输出（运行时合同）
- invoke 是 stream 的特例（消费完的最后一个 values 帧）；流式接口来自 Runnable 协议，内容来自 LLM 回调透传
- query 的第一道改写是模型填参数——用户原话不直达检索；查几轮由主图 agent 自主决定（并行/串行/不查都有）
- 帧的粒度是节点不是消息：一次快照可涨多条（并行工具），空 content 的 AI 是决策帧（content 空但 tool_calls 非空）
- stream_mode 可多开：传列表则每帧带 (模式名, chunk) 自标签，按事件时间交错输出

## 4. 可演示场景（B2 验收）

- checkpoint：step3 同进程两轮 + `--recall` 跨进程召回
- interrupt：step4 y/n 暂停恢复、`:new` 换会话（遗留实验：一条消息触发多个危险工具的批量确认）
- subgraph：step5 rewrite/retrieve/judge 全程打印可观察
- streaming：step6 `--mode` 三切换（+多开双模式）
- 对比实验（挂里程碑 C）：有无子图的正确率对照

## 5. open_deep_research 对照精读（生产级多 Agent 参考架构）

> LangChain 官方深度研究 agent（DeepResearch Bench #6）。分工示范：LangChain 管一次调用（init_chat_model/bind_tools/structured_output），LangGraph 管万次编排（状态/循环/路由/并发）。

### 5.1 三层图嵌套主干

```
主图: clarify_with_user → write_research_brief → research_supervisor → final_report_generation
                                                   └ supervisor ⇄ supervisor_tools 循环(≤6轮)
                                                       └ ConductResearch ×N(gather 并发≤5) → researcher 子图
                                                           └ researcher ⇄ researcher_tools(≤10轮) → compress_research
```

| 层 | 职责 | 上下文对象 |
|---|---|---|
| 主图 | 澄清→简报→调度→终稿；messages 只在入口/出口写入，中间研究零污染 | messages（用户面，贯穿全程） |
| supervisor | 只规划不干活：bind 3 个 schema 工具，拆题→并发派活→评估→再拆 | supervisor_messages（调度面） |
| researcher | 单兵 ReAct 搜信息，干完压成一段结论回传 | researcher_messages ×N（执行面，每任务一套，压缩后即弃） |

上下文三要素：谁创建（brief 节点 override 初始化）/谁追加（循环）/谁销毁（compress）——上下文生命周期管理本身就是架构主干。

### 5.2 子图集成两式

| | 挂载式（supervisor） | 调用式（researcher） |
|---|---|---|
| 写法 | add_node("x", 编译后子图) | 节点函数里 subgraph.ainvoke(dict) |
| 流转 | 框架按同名 key 自动入关/出关，reducer 用父图侧 | 手动构造输入、手动摘输出（命令式） |
| 收益 | 声明式，数据流向写在图定义里 | 能塞进 asyncio.gather 并发 N 份 |
| input/output 面 | 保持全量（同名机制要全开） | output 焊窄成 2 个 key，过程数据物理出不了子图 |

合并发生两次：子图内部按自己 reducer 合并 + 写回父图再按父图 reducer 合并一次。

选型准绳：
- 编译期就确定"图里必有这一环"、父子间要共享多个 state 字段 → 挂载式：数据流向声明式，checkpointer 按子图边界存档，支持断点恢复
- 运行时才知道"派不派、派几个、结果怎么包装" → 调用式：数量由模型 tool_calls 决定，gather + 切片控并发，输出手动包 ToolMessage
- 锚点：挂载是图纸上的固定工位，调用是车间主任手里的临时外包单

### 5.3 上下文工程 = 三级压缩漏斗

- 漏斗：网页级（50k 字符截断 + mini 模型摘要）→ 子 agent 对话压缩（compress_research）→ 终稿只吃压缩 notes；10 轮几十万 token 的搜索史，supervisor 只收到几百 token 结论
- 双通道：notes（压缩结论喂报告）/ raw_notes（原文留底，不喂任何模型）
- 金句：单 Agent 循环死于上下文爆炸；多 Agent 的本质 = 每个子任务干净上下文 + 压缩漏斗控制回流信息量

### 5.4 状态流转机制（标注是视图、schema 是权限）

- 节点签名的 `state: XxxState` 只是 IDE 提示，改了行为不变；真正权限在三处：StateGraph(Schema) 注册 channel / input=、output= 进出口海关 / add_node 挂载时两 schema 同名 key 边境比对
- override_reducer：默认 operator.add 拼接，传 `{"type":"override","value":[...]}` 整体覆盖（brief 初始化 supervisor_messages、终稿清空 notes 靠它）
- Command(goto, update)：路由 + 写入申请内聚节点；update 是否生效、怎么合并由 channel 的 reducer 裁决
- BSP 屏障：super-step 内所有节点（含 async）跑完 + 合并完才进下一步；async 只是让出事件循环给同步内并行节点。并发只在步内：引擎 fan-out（Send，每分支独立 checkpoint）vs 节点内 gather（ODR 选择：原子简单，代价是整步重来）

### 5.5 token 超限防御链（纵深防御）

```
预防(压缩漏斗) → 识别(is_token_limit_exceeded 按 provider 分诊: openai/anthropic/gemini 报错模式各异)
→ 局部止损(压缩失败: 砍最后一轮 AI+Tool 对, 重试×3, raw_notes 仍保底)
→ 全局止损(终稿失败: 查 MODEL_TOKEN_LIMITS 表, findings≈limit×4 字符截断, 每次×0.9, 重试×3)
→ 熔断(supervisor_tools 捕获任何异常提前 END, 已有 notes 保底出报告)
```

- 超限 = 输入上下文超限（API 4xx），非输出截断；分诊的意义：只有超限才值得截断重试，网络/鉴权错误砍历史无用
- 失败也建模成消息：压缩失败的错误串包成 ToolMessage 回传，supervisor 可见可重派
- 已知瑕疵：except 分支 `is_token_limit_exceeded(...) or True` 使分诊失效——读源码的细节证据

### 5.6 范式与技巧盘点

| 范式/技巧 | 实物 |
|---|---|
| Orchestrator-Worker + Map-Reduce | supervisor 拆题派活=Map，final report 汇总=Reduce |
| 虚拟工具协议（handoff） | ConductResearch/ResearchComplete 纯 Pydantic 无实现，tool-call 当结构化通信协议 |
| 伪装成工具的强制反思 | think_tool 零实现（返回 echo），prompt 要求每次搜索后必调——评测驱动的规划技巧 |
| 模型分层路由 | 一个 init_chat_model(configurable_fields) 实例，各节点 with_config 注入：summarization 用 mini（最频繁最便宜），research/compression/report 用大模型 |
| 优雅降级 | 摘要超时回原文、MCP 连接失败返空列表、OAuth token 到期清理 |
| 演进（bitter lesson） | legacy 固定大纲 → 新版 supervisor 动态拆题：护栏（预算/上限/压缩）而非流程脚本 |

一句话收束：token 超限要当成预期的可恢复运行状态而非异常；好架构给护栏不给流程脚本。
